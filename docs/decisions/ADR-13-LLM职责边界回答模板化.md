# ADR-13：LLM 职责边界——回答模板化，敏感数据不出网

- 状态：已接受
- 日期：2026-07-15

## 上下文
ADR-08 原定 LLM 承担「意图识别 / 参数抽取 / 工具调度 / 回答组织」。但「回答组织」需把检索到的价格 / 库存 / 报价原文作为 prompt 发送给豆包，与 ADR-11「数据不直接公网暴露」冲突。

## 决策
M1 收紧 LLM 职责边界（修订 ADR-08）：
1. LLM 只做：意图识别、参数抽取、工具选择。
2. 回答由确定性模板拼接（answer_render），LLM 不接触价格 / 库存 / 报价原文。
3. 允许出网到 LLM 的仅限：用户查询意图与 OE 号 / 车型等低敏感参数（用于抽参）。

## 理由
- M1 的回答格式本就结构化（SKU + 适配车型 + 图片 + 库存 + 价格 + 交期），模板完全够用。
- 敏感数据不出网，泄密面最小，符合 ADR-11 的安全边界。
- 意图 / 参数抽取所需文本（OE 号、车型）敏感度低，可安全送 LLM。

## 后果
- 编排层新增确定性 answer_render 模块，替代 LLM 回答组织。
- 需定义「可出网字段白名单」（OE 号、车型）与「禁出网字段」（价格、库存、报价、交期成本）。
- 未来若需自然语言自由回答，须先重估该边界（另立 ADR）。

---

## 作者批注：为什么做这个决策

ADR-08 最初让 LLM 连"回答组织"一起做，是我自己在 review 时否决的：回答组织需要把价格、库存原文塞进 prompt 发给公网模型，和部署安全边界直接冲突。修正后的边界让 LLM 变成一个"只听得懂人话、但看不见数据"的前台——它知道用户想要什么，却永远接触不到敏感数值，回答由确定性模板拼接，从根上消除了回答幻觉的业务风险。多 SKU 时"直接返回列表、不追问"这类细节，也是为了避免 LLM 自由发挥带来的不确定性。
