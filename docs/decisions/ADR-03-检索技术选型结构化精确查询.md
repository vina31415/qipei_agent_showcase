# ADR-03：检索技术选型——结构化精确查询，而非 RAG

- 状态：已接受
- 日期：2026-07-13

## 上下文
核心场景是 OE 号 → SKU、车型 → OE/SKU。数据为结构化编码/实体，非长文本。

## 决策
采用「归一化 + 关系型数据库 + B-Tree 精确索引」，**不采用 RAG / 向量检索**。

## 理由
- 数据是结构化编码，向量「语义相似」对编码无意义，反而引入错配风险。
- 2.3 万 SKU 规模，向量检索无性能优势，徒增复杂度。
- 精确查询可解释、可控（规则可调）；向量是黑盒。

## 后果
- 核心诉求「准」由确定性规则保证，不押注模型。
- 未来非结构化知识问答（售后知识/质保政策）需另立 RAG 方案。

---

## 作者批注：为什么做这个决策

2026 年做 LLM 项目，不用 RAG 反而需要写 ADR 来解释。我的判断依据很朴素：OE 号 `6Q0820803C` 和 `6Q0820803` 是不同零件，向量检索的「语义相似」在这类编码上只有害处——它会觉得两个号"很像"。查错一个 OE 号发给客户就是发错货。所以核心诉求"准"必须由确定性规则保证，模型只放在它擅长的位置（理解口语化的查询意图）。这个决策后来被 spec 全程贯彻：RAG 明确列入范围外。
