# ADR-32：ETL 同步频率与审计存储

- 状态：已接受
- 日期：2026-07-21

## 上下文
需确定产品主数据中心 ETL 的同步频率、幂等与失败重试策略，以及审计日志的存储与脱敏口径。

## 决策

### 同步频率
| 数据 | 频率 | 方式 |
|---|---|---|
| OE / 车型主数据 | 每日 | 全量 |
| 库存（现货） | 5 分钟 | 增量 |
| 在途 PO | 5 分钟 | 增量 |
| 采购周期 / 供应商交期 / 默认供应商 | 每日 | 全量 |
| 分级价（SAL_PRICEBASE） | 1 小时 | 全量 |

- 幂等：`sku_code` / `oe_normalized` 主键 upsert
- 失败重试：按 ADR-22（3 次指数退避），最终失败告警

### 审计存储
- `audit_log` 表：`request_id, user_id, role, intent, query, hit_count, is_fallback, created_at`
- 保留 90 天
- 脱敏：只记查询动作 + 命中数，不记价格/库存具体数值（避免审计表成第二个敏感数据源）

## 理由
- 库存/在途变化快 → 5 分钟增量；价格变化慢 → 1 小时全量；主数据/交期参数 → 每日全量，平衡新鲜度与金蝶 10 并发限流。
- 审计脱敏：留痕「谁查了什么动作」满足合规，不复制敏感数值。

## 后果
- `etl/` 实现定时任务（cron/调度器），按频率同步；审计日志写入 `audit_log`。
- 同步失败告警接入可观测；审计保留 90 天后清理。
