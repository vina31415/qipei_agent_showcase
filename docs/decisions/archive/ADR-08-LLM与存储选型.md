# ADR-08：LLM 与存储选型

- 状态：已接受（LLM 职责边界由 ADR-13 修订）
- 日期：2026-07-14

## 上下文
需确定 LLM 与存储选型，明确模型与确定性代码的职责分工。

## 决策
1. LLM：豆包（火山方舟），负责意图识别/参数抽取/工具调度/回答组织。
2. 编排层对 LLM 做接口抽象，可替换。
3. 存储：MySQL，产品主数据中心 B-Tree 索引，不引入向量库。

## 理由
- 重活（归一化/检索/交期）在确定性代码，模型只做轻活；豆包在中文 + function calling 成熟、成本低、国内合规。
- 2.3 万 SKU + 十万行级映射，MySQL 足够。

## 后果
- 参数抽取需「规则优先、模型兜底」以保可控。
- 未来若换模型，仅改编排层适配器。
- 「回答组织」已由 ADR-13 修订：M1 改为模板拼接回答，LLM 不接触价格/库存/报价原文。
