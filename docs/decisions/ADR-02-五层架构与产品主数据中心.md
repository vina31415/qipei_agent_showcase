# ADR-02：五层架构 + 产品主数据中心

- 状态：已接受
- 日期：2026-07-13

## 上下文
需确定系统整体架构，使同一套能力经多渠道复用，检索复杂度与业务逻辑解耦。

## 决策
采用「五层 + 一数据地基」：
渠道层 / 编排层 / 能力层 / 集成层 / 横切层 + 产品主数据中心（MySQL）。

## 理由
- 渠道与核心解耦：同一套能力通过多前端暴露，渠道只做消息适配。
- 能力层工具化：每个能力独立、可复用、可单独测试。
- 数据地基独立：检索复杂度与业务逻辑分离，主检索源单一权威。

## 后果
- 渠道层新增入口成本低（只是加一个适配器）。
- 数据地基（ETL + 归一化）是独立工作块，需单独排期。

---

## 作者批注：为什么做这个决策

这个项目一开始最大的诱惑是「直接做一个聊天机器人」。我刻意先定分层：渠道层只做消息适配，能力层把每个业务能力工具化。理由是汽配查询的复杂度在数据（OE 归一化、分级价、交期规则），不在对话——如果对话逻辑和业务规则揉在一起，后面接 WhatsApp、接企微都要重写一遍业务。单独抽出的「产品主数据中心」是整个系统最贵的部分（ETL + 归一化），但也是命中率 70%→98% 的唯一支点：先把数据洗干净，检索才能又快又准。
