# ADR-09：成功标准与验收指标

- 状态：已接受
- 日期：2026-07-15

## 上下文
需为第一里程碑定出可事后检验的量化成功标准，作为验收与测试的基线。业务方已确认四项指标。

## 决策
1. OE 检索命中率 ≥ 98%（口径：端到端，含 ERP 兜底后最终给出正确 SKU 的比例）
2. 「OE → 库存 → 价格 → 交期」从多步人工操作收敛为 1 轮对话（允许澄清追问）
3. 端到端查询响应 P95 ≤ 3 秒
4. 红线：交期 / 下单零自动落库，100% 由人确认

## 理由
- 命中率由业务方明确要求 98%（较原 70% 现状大幅提升），是 OE 归一化规则覆盖度与兜底策略的最上游约束；口径取端到端（含兜底），业务真正在乎的是「问一句、答得对」。
- 其余三项为业务方认可的验收口径，后续功能验收标准与测试场景据此派生。

## 后果
- 四项指标将逐条映射为 spec 第 4 章「验收决策」的功能验收标准。

---

## 作者批注：为什么做这个决策

我把"成功"写死在 spec 里而不是写在 PPT 里，是吸取了常见的教训：AI 项目最容易死在"效果不错"这种无法证伪的表述上。四个指标全部是事后可检验的口径——98% 命中率是业务方基于现状 70% 提出的、P95≤3s 含兜底耗时、零落库可以用代码审查证明。后来 plan 的每个测试步骤都是从这四条派生的，ADR-38 还为"命中率怎么算"单独定义了判定口径。先定尺子，再动工。
